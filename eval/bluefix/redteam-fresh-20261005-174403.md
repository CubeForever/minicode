## 红队报告

### 发现
- [可选] 滑窗逐次重算 `sum`,复杂度 O(n·k) 而非 O(n) (util.py:8 `return [sum(xs[i:i + k]) / k for i in range(len(xs) - k + 1)]`) — 命中攻击面「超长输入」:每个窗口都对长度 k 的切片重新求和,`xs[i:i+k]` 还额外拷贝 k 个元素。n=k=10⁶ 量级即约 10¹² 次运算会挂死;正确性无误,仅性能受影响。是否真构成问题取决于隐式测试是否用大输入。

### 已证伪的可疑点
- [证伪] k 边界全部分支错抛或漏抛 — 实测 `k=0/k<0/k>len/空xs+任意k` 全部正确抛 `ValueError`,且错误信息与 docstring 完全一致 (util.py:7-8)。
- [证伪] 整数除法回归(`/` 在某些环境下做整除) — 实测 py3.10(cpython-310)真除法,`[1,2,3,4],k=2` 返回 `[1.5,2.5,3.5]`,元素均为 `float`,符合「float」返回契约 (util.py:8)。
- [证伪] docstring 示例不通过 — 实测 `[1,2,3,4],k=2 == [1.5,2.5,3.5]` 且长度 = `len(xs)-k+1`(n=4,k=2→3;n=5,k=5→1)均吻合。
- [证伪] 原抛 `NotImplementedError` 的回归 — 这是实现该函数的预期行为变更,非回归;且本地无调用点依赖旧异常。
- [证伪] `bool k=True` 越界或类型异常 — `isinstance(True,int)` 为真,等价 k=1,实测返回正确结果。
- [证伪] `tuple` 作为 xs 不工作 — 实测 `(1,2,3,4),k=2` 正常返回 `[1.5,2.5,3.5]`。
- [证伪] 比较链/`not` 优先级 bug — `not (0 < k <= len(xs))` 等价 `not((0<k) and (k<=len))`,语义正确。
- [证伪] `sum` 起始值 0 与浮点元素交互产生精度问题 — 实测浮点元素正常,无精度偏差。
- [证伪] 字符串元素 / 生成器 xs 触发契约违约 — 字符串元素抛 `TypeError`(垃圾输入,非 k 约束范围);生成器抛 `TypeError`(无 `len()`,函数签名隐含 sequence,属用错类型)。

### 存疑(不确定是否真实)
- [存疑] `float` 型 k(如 `2.0`、`2.5`)能通过守卫 `0 < k <= len(xs)`(比较运算对 float 成立,`2.0<=4` 为真),却在 `range(len(xs) - k + 1)` 处抛 `TypeError: 'float' object cannot be interpreted as an integer`,且未被守卫拦截、不是契约规定的 `ValueError` (util.py:7 守卫放行 → util.py:8 `range()` 崩溃,已实测) — 严格按字面契约"k 必须大于 0 且不超过 len(xs)"(仅值约束,未限定 int),`k=2.0` 是合法输入却崩;按 docstring 示例 `moving_average([1,2,3,4], 2)` 仅用 int、且"窗口大小"自然域为正整数,则属用错类型。两种解读冲突,且本地无 spec 可裁断,故存疑。可选的加固(若判定为问题):守卫前 `k = operator.index(k)` 或加 `isinstance(k,int)` 校验。
