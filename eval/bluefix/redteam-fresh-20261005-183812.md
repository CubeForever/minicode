## 红队报告

### 发现
- [应修] `isinstance(k, int)` 拒绝满足幅度约束的非整型 k,偏离 docstring 合同 (util.py:7) — docstring 只规定抛 ValueError 的条件为"k 必须大于 0 且不超过 len(xs)",未要求整型。`moving_average([1,2,3,4], 2.0)` 满足 `0 < 2.0 ≤ 4` 却被拒,且报错信息"k 必须大于 0 且不超过 len(xs)"完全不提类型,误导调用方。这是 spec-conformance 任务的合同漂移。影响面小(隐藏测试未必测浮点 k),但属真实偏离。

### 已证伪的可疑点
- [证伪] 布尔 k 静默通过(`isinstance(True,int)` 为 True) — `moving_average(xs, True)` 当 k=1 处理,而 spec 的 ">0" 对 True(==1)成立,代码允许其通过反而与 spec 一致;False==0 走 `k<=0` 分支正确抛错。语义虽怪但符合合同,非缺陷。
- [证伪] 空输入 `xs=[]` — 任何 k≥1 都满足 `k > len(xs)=0` 而抛 ValueError;docstring 的长度公式 `len-k+1` 仅在 k≤len 时成立,空输入应抛而非返回 [],与显式约束一致。
- [证伪] `k == len(xs)` 边界 — `range(k, len(xs))` 为空,返回单元素 `[mean]`,长度 1 = `len-k+1`,正确。
- [证伪] `k == 1` 边界 — `xs[i]-xs[i-1]` 退化为相邻差,window_sum 恒为 xs[i],返回各元素 float 化,长度 `len`,正确。
- [证伪] 结果元素类型非 float — Python 3 `/` 恒为真除法,`sum([2,4])/2==3.0`,即使整除也返回 float,符合"（float）"。
- [证伪] 长度 off-by-one — 初始 1 元素 + `range(k, len(xs))` 的 `len-k` 次迭代 = `len-k+1`,与 docstring 一致。
- [证伪] 滑动和浮点漂移/累加误差 — 这是标准滚动窗口算法的固有取舍,非实现缺陷;整数输入下精确,浮点输入下为常规 IEEE754 行为。
- [证伪] numpy 整型被 `isinstance` 误拒 — 纯推测,本仓无 numpy 依赖(仅 util.py),不在评审范围。
- [证伪] 输入被修改 — 仅读取 `xs`,无任何写入。
